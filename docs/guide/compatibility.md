# 兼容性与验证

| 能力 | 边界 |
| --- | --- |
| 应用界面 | Android 8.0+，中英文 |
| Shizuku 用户服务 | Shizuku API 13，持续授权连接 |
| 虚拟屏幕 | 隐藏任务接口、多屏支持，受设备固件影响 |
| 最近任务返回 | 检测系统实际移回主屏，不能强制桌面支持跨屏恢复 |
| 控件树与输入 | 固件允许 UiAutomation 连接；可选无障碍输入桥接 |
| 查找与控件宏 | 仅可访问节点；Canvas、游戏与部分 WebView 可能不暴露完整元数据 |
| 截图 | 主屏允许捕获；受保护内容可能为空或被拒绝 |
| 隐私信息本 | Android Keystore 与已录入的强生物识别 |
| 无障碍保持 | 重新开启从设置中消失的服务，不覆盖所有服务崩溃 |

CI 设备矩阵覆盖 API 26 和 35，检查启动、导航、语言切换和信息本操作。单元测试覆盖截图重叠匹配及 RFC TOTP 测试向量，另有宏超时、取消与选择器歧义检查。模拟器界面测试通过不代表已经验证 Shizuku 授权、厂商任务移屏、最近任务恢复或第三方应用行为，这些需要真实设备验证。

虚拟屏幕可以提高应用持续呈现的机会，但不能覆盖低内存策略、电池限制、厂商进程管理与应用自身生命周期行为，不承诺“永不被杀”。

Shell 用户服务复用 Shizuku 提供的 Android 运行环境，上下文创建与 UiAutomation 连接互不连带失败。初始化日志包含失败阶段、底层异常与堆栈，连接失败后以 30 秒间隔重试。截图优先使用 UiAutomation，失败时使用 shell `screencap`，限制输出量及五秒执行时间。冻结截图在控件树不可用时保留为普通图片，预览和快照元数据明确标记缺失。长截图可使用整屏采集与手势滚动；若已选择保留或忽略控件规则但无法获取控件树，则停止采集，防止导出未经遮罩的画面。

CI 在两个 API 版本额外通过 `adb shell app_process` 启动仅调试包包含的探针，验证运行环境复用、UID 2000 的 UiAutomation 连接、冻结图片与控件树传输，以及独立截图备用路径；这不等同于验证 Shizuku 授权握手或厂商固件。

UiAutomation 是系统独占连接。“already registered”会标记为占用，不会强行断开其他工具。可在首页主动点击“启用控件兼容通道”，通过 Shizuku 开启本应用无障碍服务；服务连接后，控件树、冻结控件信息、查找、控件宏与输入可使用原生兼容通道，截图继续使用 shell。若占用通道的工具暂停了全部无障碍服务，则需先让其释放连接。“重试控件连接”不会销毁隐藏任务。控件键与来源通道、本次快照绑定，过期键不能静默切到另一通道执行。
